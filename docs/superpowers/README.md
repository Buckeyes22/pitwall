# Plans and specs (historical records)

Everything under `docs/superpowers/` is a dated record of how a piece of work was designed and
carried out. The plans and specs name commands, files, environment variables, and line numbers as
they were on the day they were written; many of those no longer exist. They are evidence of intent
and history, not instructions for the current release, and they are not kept in step with the code.

For current behavior read the maintained documentation instead:

- [`docs/sdlc/`](../sdlc/README.md): the source-grounded technical documentation.
- [`docs/agents/`](../agents/README.md): Agent Routing (`pitwall agents`).
- [`docs/operator/`](../operator/): operator guides, including the
  [migration guide](../operator/agents-migration.md) for workstations that ran the standalone tools.
- [`CHANGELOG.md`](../../CHANGELOG.md): what changed in each release.

`plans/` holds implementation plans and their execution ledgers; `specs/` holds the design documents
they implement. The plan and ledger for the unification into one product
(`plans/2026-09-28-single-project.md`, `plans/2026-09-28-single-project-ledger.md`, and
`specs/2026-09-28-single-project-design.md`) explain why the repository looks the way it does.
