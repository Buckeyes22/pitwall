# Pitwall 0.2.0a1

This alpha is the first unified release. Pitwall, Agent Routing, the free-tier gateway, and the Pi
workbench are one Python package with one `pyproject.toml`, one lock file, one version line, and `v*`
tags only. Like the earlier alphas it is a GitHub-first release: Python distributions are attached to
this release and the five service images are published to GHCR. PyPI publication stays deferred.

## Highlights

- One install and one command. Installing from a checkout of `v0.2.0a1` puts `pitwall` on your `PATH`, and
  `pitwall agents install` wires the shims, the Claude Code, Codex, and GitHub Copilot CLI plugins,
  and the channel MCP server into your hosts.
- Agent Routing is `pitwall agents`. Agent profiles (`name@harness`) live in the `[agents.profiles]`
  tables of `pitwall.toml`, and the `SHIM-DONE exit=N` contract is unchanged.
- `pitwall agents migrate` moves a workstation that ran the standalone tool across in one
  idempotent step; see the [migration guide](../operator/agents-migration.md).
- The gateway is a Python service, `pitwall gateway serve`, with its catalog pinned to omniroute
  3.8.50.
- The Pi workbench is `pitwall workbench`, with the pinned Pi 0.84.4 installed by
  `pitwall agents setup pi`.
- One readiness report: `pitwall doctor` covers the broker, agents, gateway, and workbench.
- Providers declare their own routing, lockout, seed, reconciler, and OpenAI-proxy behaviour in
  their adapters, and code with no production caller was removed.

## Breaking changes

This is a clean break with no aliases. The old commands, environment variables, paths, and the
`subagent-model-routing-local` marketplace name are gone; the
[changelog](../../CHANGELOG.md) has the full mapping, and `pitwall agents` refuses to run while a
legacy environment variable is set and names its replacement.

- `pitwall-agent-routing <cmd>` becomes `pitwall agents <cmd>`, and `routes` becomes `profiles`.
- `pitwall-mcp` becomes `pitwall mcp serve broker`; the channel server is
  `pitwall mcp serve channel`.
- `SUBAGENT_MODEL_ROUTING_*` and `PITWALL_AGENT_ROUTING_*` become `PITWALL_AGENTS_*`, and
  `SHIM_TIMEOUT_SECS` becomes `PITWALL_AGENTS_TIMEOUT_SECS`.
- `pitwall-gateway` becomes `pitwall gateway serve`, and `pi-workbench` becomes `pitwall workbench`.
- The dispatch prerequisite for GNU `timeout` or `gtimeout` is gone.

The [changelog](../../CHANGELOG.md) lists every change.

## Important limitations

- This is pre-1.0 alpha software; breaking changes can occur under the documented
  [compatibility policy](../compatibility.md).
- Pitwall does not ship a GPU worker image. Operators supply the image or existing RunPod endpoint
  that performs inference.
- RunPod carries live evidence for this release. Vast.ai, Together, and Lambda Cloud adapters are
  code-complete without a live countersign; see the [support matrix](../support-matrix.md).
- No keyless free pool served anonymous callers in the 2026-09-23 benchmark; free routing needs
  pools you hold keys for.
- Deployment is self-hosted. Operators remain responsible for infrastructure, provider
  credentials, workload data, model and image provenance, and spend.

## Installation and verification

Install the CLI from a checkout of `v0.2.0a1` with
`uv tool install --python 3.14.7 .`, or download the wheel or source archive and `SHA256SUMS` from this
release. The container images use the following namespace:

`ghcr.io/buckeyes22/pitwall/<service>:v0.2.0a1`

Prefer immutable image digests in deployed configurations. Verify downloaded artifacts against
`SHA256SUMS` and the GitHub attestations before use.

Please report vulnerabilities privately according to the [security policy](../../SECURITY.md).
Use GitHub Discussions for support and general questions.
