# Pitwall 0.3.0a1

This alpha moves the broker and the orchestrator channel to MCP protocol 2026-07-28, makes repeated
`idempotency_key` calls safe on paid operations, adds ZCode as the fourteenth routing harness, and
closes a long list of budget, credential, and error-handling defects found in release review. Like
the earlier alphas it is a GitHub-first release: Python distributions are attached to this release
and the five service images are published to GHCR. PyPI publication stays deferred.

## Highlights

- MCP 2026-07-28. The broker (now on the MCP Python SDK 2, `mcp>=2.3.0,<3`) and the channel serve
  stateless requests, `server/discover`, cache hints, and `subscriptions/listen` as well as the
  legacy `initialize` handshake. Every tool has a title and behavior annotations, every broker
  parameter is described, an unknown tool is JSON-RPC error -32602, and tool calls are rate limited.
- Safe retries on paid calls. A repeated `idempotency_key` replays the stored RunPod control-plane
  result, and `POST /v1/leases`, `pitwall_lease_pod`, and `pitwall_serve_model` return the existing
  lease instead of launching a second pod. A create whose outcome is unknown is resolved by a
  `PITWALL_CREATE_ATTEMPT` pod marker, and no pod is terminated without proof that it is ours.
- Lease spend always reaches the budget, and an unset or invalid budget answers 503
  `budget_not_configured` instead of a 500.
- ZCode (`zcode`) joins as a routing harness, and `pitwall-channel` registers for Grok, Antigravity,
  Muse, Hermes, and goose so each can run as a managed child that asks its parent.
- A run whose supervisor was killed is recorded `failed` with an `abandoned.json`, and the harness it
  left behind is ended.
- New model facts: Claude Haiku 5.5, Claude Opus 5, GPT-6.1 Sol (replacing `gpt-6-sol` for the
  `codex` harness), and the Xiaomi MiMo V2.6 releases.

## Breaking changes

- Agent Routing runs each harness CLI under its own sandbox and approval policy unless
  `PITWALL_AGENTS_UNRESTRICTED=1` is set; unset used to mean unrestricted. Set `=1` to keep
  unattended dispatch, which Kimi Code and dsh require.
- `pitwall` now requires the MCP Python SDK 2 (`mcp>=2.3.0,<3`).
- `gpt-6-sol` is no longer registered for the `codex` harness; use `gpt-6.1-sol`.
- `grok-4.5` is no longer offered through the Grok CLI, which rejects it.
- The capability audit's headroom details key `required_estimate_usd` is now
  `required_ceiling_usd`.
- Migrations `0041` to `0043` apply on `pitwall db migrate`; `0043` adds a nullable
  `pitwall.idempotency_keys.body_hash` column.

The [changelog](../../CHANGELOG.md) lists every change.

## Important limitations

- This is pre-1.0 alpha software; breaking changes can occur under the documented
  [compatibility policy](../compatibility.md).
- Pitwall does not ship a GPU worker image. Operators supply the image or existing RunPod endpoint
  that performs inference.
- No provider credential or spend was authorized for this release candidate, so the provider
  adapters are code-complete without a live countersign; see the
  [support matrix](../support-matrix.md).
- Deployment is self-hosted. Operators remain responsible for infrastructure, provider
  credentials, workload data, model and image provenance, and spend.

## Installation and verification

Install the CLI with `uv tool install --python 3.14.7 https://github.com/Buckeyes22/pitwall/releases/download/v0.3.0a1/pitwall-0.3.0a1-py3-none-any.whl`, or from a checkout of the `v0.3.0a1` tag with
`uv tool install --python 3.14.7 .`, or download the wheel or source archive and `SHA256SUMS` from this
release. The container images use the following namespace:

`ghcr.io/buckeyes22/pitwall/<service>:v0.3.0a1`

Prefer immutable image digests in deployed configurations. Verify downloaded artifacts before use:

```bash
gh release download v0.3.0a1 --repo Buckeyes22/pitwall -D pitwall-v0.3.0a1
cd pitwall-v0.3.0a1 && sha256sum -c SHA256SUMS
gh attestation verify pitwall-0.3.0a1-py3-none-any.whl --repo Buckeyes22/pitwall
```

Each image's published digest is in `<service>.digest` and its SBOM in `<service>.spdx.json`.

Please report vulnerabilities privately according to the [security policy](../../SECURITY.md).
Use GitHub Discussions for support and general questions.
