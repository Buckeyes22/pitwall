# 24 — Pitwall Gateway

The Pitwall Gateway is a hardened loopback HTTP server that fronts free-tier inference pools for
Pitwall. It is part of the `pitwall` Python package (`pitwall.gateway`) and starts with
`pitwall gateway serve`. It serves only loopback traffic, requires a bearer token, and relays
OpenAI-shaped requests to the upstream named by a route table. It is not a remote service, a public
proxy, or a multi-tenant router.

Earlier releases shipped the gateway as a Node package forked from OmniRoute's `open-sse/`. That
package is gone: the gateway is now a Python ASGI application with the same surface. OmniRoute
survives only as the pinned source of the free-model catalog (see "Catalog" below).

## Purpose and scope

The gateway gives Pitwall one observable front door for budgeted free-tier inference. The broker's
`openai_gateway` provider adapter and the OpenAI proxy executor send every request here with an
`x-pitwall-route: <provider name>` header. The gateway rewrites `model` to the route's model id,
sends the route's own upstream key (never the inbound token), and relays the answer. ADR 0007
records the terms-of-service posture and what the gateway deliberately does not do (browser
fingerprint transport, image/audio/search generation, web-session executors).

## Components

| Module | Role |
| --- | --- |
| `pitwall.gateway.app` | ASGI app (`GatewayApp`, `create_app`) and the `serve` entry point that runs it under uvicorn. Written directly against ASGI so a truncated upstream stream aborts the connection instead of closing it normally. |
| `pitwall.gateway.config` | `resolve_config`, `GatewayConfig`, `is_loopback`. Fail-closed validation of the token, `--bind`, `--port`, and the upstream settings. |
| `pitwall.gateway.auth` | `GatewayAuth`: one constant-time bearer comparison (`hmac.compare_digest`) and one `TokenBucket` per authenticated token. |
| `pitwall.gateway.routes_table` | `load_route_table`, `resolve_route`, `GatewayRoute`, `RouteRefusal`: the provider-name to upstream table. |
| `pitwall.gateway.relay` | `relay_chat`, `relay_embeddings`, `Deadlines`, `RelayResult`: the upstream call, SSE relay, and error redaction. |
| `pitwall.gateway.translation` | `translate_inbound`: projects `claude` and `gemini` request bodies to an OpenAI `messages` array. |
| `pitwall.gateway.compression` | `compress_request`: the lite compression pass. |

Executors (per-model handlers that replace the upstream relay) are injected into `create_app`;
there is no module-level registry. The launcher used by the supervisor is
`[sys.executable, "-m", "pitwall", "gateway", "serve"]` (`pitwall.personal.gateway:default_argv`).

## Surface

The server listens on loopback only and serves exactly five routes:

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| POST | `/v1/chat/completions` | Required | OpenAI-shape chat completion proxy |
| GET | `/v1/models` | Required | Route names and executor ids (route-table mode), or executor ids plus the upstream catalog (single-upstream mode) |
| POST | `/v1/embeddings` | Required | OpenAI-shape embedding proxy |
| GET | `/health` | Required | Token-authenticated liveness probe (`{"status":"ok","service":"pitwall-gateway"}`) |
| GET | `/internal/telemetry` | Required | Operator telemetry: bind, port, body cap, rate limit, redacted upstream label, executor count |

A wrong method on one of these paths returns a structured `405` with an `Allow` header. Unknown
paths return the structured `404` envelope. Every response carries `x-request-id`.

### Boot configuration

- `PITWALL_GATEWAY_TOKEN` is required. The supervisor passes it through the environment, never
  argv. An empty token refuses to boot.
- `--bind` accepts only `127.0.0.0/8`, `::1`, `localhost`, `ip6-localhost`, or `ip6-loopback`
  (`pitwall.gateway.config:is_loopback`). IPv4-mapped IPv6 forms and DNS names that merely start
  with `127.` are refused. The default is `127.0.0.1`.
- `--port` defaults to `20130` and must be a full unsigned decimal integer in `[0, 65535]`. Port
  `0` stays valid for ephemeral binding; junk, fractions, signs, exponents, and hex are rejected.
- `PITWALL_GATEWAY_BODY_CAP_BYTES` (default 1 MiB) and `PITWALL_GATEWAY_RATE_LIMIT_RPM` (default
  120) must be positive integers when set.
- An upstream is required: either `PITWALL_GATEWAY_ROUTES` (a route table file) or
  `PITWALL_GATEWAY_UPSTREAM_URL` (single upstream, with an optional
  `PITWALL_GATEWAY_UPSTREAM_API_KEY` forwarded as its bearer token). Boot fails closed when
  neither is set.

`pitwall gateway serve` prints `pitwall-gateway failed to start: <reason>` and exits `1` on any
configuration error. `--help` prints usage and exits `0`; an unknown flag or a flag missing its value
exits `2` with the standard usage error.

### Route table

`PITWALL_GATEWAY_ROUTES` names a JSON file (`schema_version` 1, a `routes` object) generated by
`pitwall gateway sync` and shipped as `config/gateway-routes.json`; the supervisor sets the
variable. Each route is keyed by the seed provider name and gives the upstream `base_url`, the
upstream `model_id`, the `api_key_env` variable holding that pool's key, and `key_required`. Key
values are read from the environment once at load time and never logged.

- A missing `x-pitwall-route` header is `400 route_required`, an unknown route `404
  route_not_found`, and a key-required route whose variable is unset `503 upstream_key_missing`.
  None of these contacts an upstream.
- With a route table loaded, `GET /v1/models` lists the route names and registered executor ids
  without an upstream call.
- In single-upstream mode, `GET /v1/models` lists the registered executor ids and the
  upstream's OpenAI `/models` catalog, deduplicated by id (a local executor id wins). Upstream ids
  are relayed verbatim; the gateway invents no model id. The listing sends the configured upstream
  key (never the inbound client token), honours the upstream timeout, and aborts on client
  disconnect. A non-2xx, malformed, failed, or timed-out listing is a structured `502
  bad_gateway` or `504 gateway_timeout`; a failed upstream is never turned into an empty `200`. A
  genuinely empty upstream catalog is a healthy `200` with `data: []`.

### Request handling

- Anonymous requests on every route, including `/health`, get `401 authentication_error`. An
  unauthenticated `GET /v1/models` does not contact the upstream.
- Each authenticated token gets `PITWALL_GATEWAY_RATE_LIMIT_RPM` requests per rolling 60 s
  window on every route except `/health`. Excess requests get `429 rate_limit_exceeded` with `Retry-After`; admitted requests
  carry `x-ratelimit-remaining`.
- The body cap (`PITWALL_GATEWAY_BODY_CAP_BYTES`, default 1 MiB) is enforced before JSON parsing:
  an oversized body gets `413 payload_too_large`.
- The JSON root must be an object, and `messages`, when present, must be an array of objects.
  Caller-shape faults are `400 bad_request`; internal faults stay `500 api_error`.
- Inbound shape is chosen with `x-pitwall-inbound-shape: openai | claude | gemini | responses`
  (default `openai`). `openai` and `responses` bodies are forwarded unchanged (no
  Responses-to-Chat conversion). `claude` and `gemini` bodies get a `messages` array projected from
  their text content; tool calls, images, and prompt-cache markers are outside the surface.
- `x-pitwall-compression: off | rtk | caveman | stacked` (default `off`) selects a lite pass:
  whitespace collapse on string messages plus consecutive-duplicate-line removal on system
  messages. The three non-`off` selectors run the same pass; the upstream compression engines are
  not part of Pitwall.
- Upstream `text/event-stream` responses are relayed incrementally. The first chunk must arrive
  within the upstream deadline and each later chunk within the idle deadline (both
  `upstream_timeout_s`, 30 s); a healthy stream is never cut by a total-time limit. On a deadline
  or upstream failure the relay sends one terminal SSE error event and aborts the connection, so a
  truncated stream never ends with a normal close.
- A client disconnect cancels the in-flight upstream request for chat, embeddings, and model
  listing.
- Only `x-ratelimit-*` and `ratelimit*` upstream headers reach the client; the broker's quota
  lockout reads reset timing there. Upstream `401`, `403`, and `407` keep their status, but
  their bodies are never passed through (the client receives the gateway's own error envelope);
  every other upstream error body, streamed or not, is redacted (credentials, stack traces,
  internal paths) and bounded before it reaches the client.
- The error envelope is `{"error":{"type","message","request_id","code"}}`. Stack traces never
  appear in response bodies; the 500 path logs the original trace server-side.
- Provider rows stay `supports_streaming=false` unless their upstream and model contract has been
  verified; the server's transport ability alone does not make a catalog row stream-capable.

## Catalog

`pitwall gateway sync` builds the free-model catalog (`config/gateway-catalog.json`), its lock
(`config/gateway-catalog.lock.json`), the route table, and the seed files from a pinned OmniRoute
npm release. The lock currently pins `upstream_version` `3.8.50`. `pitwall gateway sync --version
<x.y.z>` selects another release and `pitwall gateway status` shows the lock and live quota state.
The gateway server itself contains no OmniRoute code, so no upstream TypeScript, `wreq-js`,
BoringSSL, ICU4X, or Mozilla-CA notice chain ships with it. Attribution for the catalog data is in
`docs/legal/gateway-attribution-review.md`.

The wheel bundles the public catalog, lock, and two seed files under
`pitwall/gateway_catalog/data`. `pitwall gateway status` and `pitwall gateway doctor` prefer a
current workspace containing config or seed, then the source checkout, then installed package
data (`pitwall.cli.gateway`). An incomplete workspace remains an error; packaged defaults do not
hide its drift. Catalog availability does not configure upstream credentials or prove inference.

## Commands

| Command | Purpose |
| --- | --- |
| `pitwall gateway serve [--bind ADDR] [--port N]` | Run the loopback gateway in the foreground |
| `pitwall gateway sync` | Sync the catalog from a pinned OmniRoute release, or apply benchmark verdicts |
| `pitwall gateway status` | Show the catalog lock and live quota state |
| `pitwall gateway doctor` | Check gateway supervision preconditions |
| `pitwall quotas` | Show the free-pool quota burn-down |
| `pitwall serve --gateway` | Start the loopback gateway sidecar before serving a model |

## Testing

The gateway is covered by the root test suite: `tests/gateway/` (app, auth, compression, config,
models, relay, surfaces, translation), `tests/cli/test_gateway_cli.py`, and
`tests/test_gateway_catalog.py`. They are hermetic; no test contacts a live upstream. Run them with
`make test-fast`.
