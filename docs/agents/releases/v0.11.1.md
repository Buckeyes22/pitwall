# Pitwall Agent Routing 0.11.1

Pitwall Agent Routing 0.11.1 ships the orchestrator ↔ subagent channel and the `pitwall` plugin
rename. It is the code tagged as 0.11.0 on 2026-09-18 plus the release metadata that tag lacked;
0.11.0 published no assets. The release uses the namespaced tag `agent-routing/v0.11.1`; broker
`v*` tags, gateway `gateway/v*` tags, and service images remain separate.

## Highlights

- A subagent can ask its orchestrator a question and keep working, or pause until the answer
  arrives, through a per-dispatch mailbox. Asks carry a default, a deadline derived from the
  dispatch's remaining time, and a per-dispatch cap; an unanswered ask resolves to its default.
- Orchestrators answer from the CLI (`inbox`, `answer`), from a workflow (`wait_for_answer`,
  `autoAnswer`), or from the D3 policy answerer, which records `policy:<model>` provenance.
- Steering: an advisory steer, a tier-2 PreToolUse gate for the Claude Code and Codex bundles,
  and a graceful abort that leaves a receipt.
- `pitwall-agent-routing mcp` is a stdio MCP server exposing the ask and inbox tools;
  `setup mcp` (or `install.sh --with-mcp`) registers it for six harnesses and `doctor` checks the
  handshake and every registration.
- The plugin family is now `pitwall`: marketplace `pitwall`, plugin `pitwall@pitwall`, agent types
  `pitwall:<shim>`. The `model-routing` script is gone; use `pitwall-agent-routing`.

## Compatibility and migration

Ledger paths, environment variable names, the `SHIM-DONE` sentinel, and persisted record schemas
are unchanged. Claude Code users on the old marketplace must remove
`subagent-model-routing-claude@subagent-model-routing`, add the payload directory as marketplace
`pitwall`, and install `pitwall@pitwall`; skills and agents are addressed as `pitwall:*` from then
on. Update a durable source install with the bootstrap command for this tag, then run
`claude plugin marketplace update pitwall`.

## Release assets

The GitHub prerelease contains a wheel, sdist, `SHA256SUMS`, installed-wheel SPDX JSON, and GitHub
build attestation. Both Python artifact forms are built twice, inspected with explicit allowlists,
and exercised outside the checkout on Python 3.14.7 before publication.
